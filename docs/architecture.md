# Архитектура

~~~mermaid
flowchart LR
    ZUP[1С] --> OQ[Исходящая очередь]
    OQ --> CORE[Оркестратор]
    CORE --> MAP[Карта ID]
    CORE --> PRINT[Печатные формы]
    CORE --> HTTP[HTTP-адаптер]
    HTTP --> API[Mock HR API]
    API --> IQ[Входящая очередь]
    IQ --> ZUP
    CORE --> LOG[Безопасный журнал]
    IQ --> LOG
~~~

## Исходящий поток

1. Событие записывается в очередь вместе с ревизией объекта.
2. Worker атомарно захватывает доступный элемент.
3. Оркестратор разрешает зависимости и строит ключ идемпотентности.
4. Печатные формы отправляются как отдельные вложения с SHA-256.
5. После 401 транспорт обновляет сессию и повторяет запрос один раз.
6. Результат переводит элемент в завершение, повтор или постоянную ошибку.

При завершении worker сравнивает ревизию. Если объект изменён во время HTTP-вызова, новая редакция остаётся в очереди.

## Входящий поток

1. Poller сохраняет задания по внешнему ID.
2. Worker захватывает задание под блокировкой.
3. Повтор проверяет, не создан ли локальный документ ранее.
4. Внешнее задание завершается после фиксации локального результата.
5. Неоднозначный поиск останавливает обработку.

## Владение данными

| Данные | Источник истины |
|---|---|
| Кадровые события и формы | 1С |
| Этап внешнего процесса | HR-платформа |
| Связи ID | Карта интеграции |
| Доставка и повторы | Очереди |
| Диагностика | Безопасный журнал |

Обмен использует eventual consistency: локальные операции атомарны, сетевые команды повторяемы и идемпотентны.

## Границы переиспользуемых компонентов

1. `HrIntegrationQueuePolicy` вычисляет claim, lease, завершение, повтор и dead-letter без ввода-вывода.
2. `HrIntegrationQueueRepository` координирует compare-and-swap, предоставленный адаптером хранилища.
3. `HrIntegrationDTOMapper` строит нейтральные структуры по декларативным правилам.
4. `HrIntegrationAttachments` валидирует двоичные вложения и устраняет дубли по SHA-256.

Реализация хранилища обязана обеспечивать уникальность ключа идемпотентности и проверку версии в одной транзакции.
Завершение и фиксация ошибки допустимы только владельцу неистекшей аренды. Истекшая аренда может быть захвачена снова.
