# Идемпотентность

Ключ операции:

~~~text
SHA-256(lowercase(kind) | stable-source-id | revision)
~~~

Дата запуска, номер попытки и ID сессии в ключ не входят. Ревизия меняется только при изменении бизнес-события.

## Защита от дублей

1. Уникальный ключ локальной очереди.
2. Идемпотентный ключ HTTP-запроса.
3. Восстановление внешнего ID по точным бизнес-признакам.
4. Дедупликация вложений по ID документа и SHA-256.
5. Уникальный внешний ID входящего задания.

После timeout команда повторяется с тем же ключом. Ответ `created` или `duplicate` завершает операцию и сохраняет
внешний ID.

## Миграция ID

- старый ID связывается с локальным объектом;
- новый ID проверяется на конфликт;
- повтор не создаёт вторую связь;
- неоднозначность требует ручного решения.
